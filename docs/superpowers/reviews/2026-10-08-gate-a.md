# Gate A review — engine plan (sub-plan 1)

**Reviewed:** the Gate A pack (engine plan, spec, research) at `7aa9dea`.
**Reviewers:** @ca-ruz (2026-10-08) and @chrisguida (2026-10-08). Both requested changes before Gate A.
**Response:** every finding was checked against the plan text and against upstream source (Bitcoin Knots `v29.4.2.knots20260508`, Bitcoin Core 29.1/30.0, BDK 3.2 / bdk_chain 0.23.3, rust-bitcoin 0.32.8, secp256k1 0.29.1, bip39 2.2.2, arti-client 0.46, rustls-webpki 0.103, `ur` 0.5.0, Fulcrum upstream and privkeyio `v2.1.2-blake-3`, BCR-2020-007/015) before any change was made.
**Status:** amendments in progress on branch `gate-a-amendments`. Coding still waits for both reviewers to approve the amended plan.

Verdicts: **Confirmed** = the finding is correct as stated. **Partly** = correct in substance, with a correction noted. **Disputed** = not correct as stated, with evidence.

The reviewers' headline result stands: the consensus port (v2 headers, BLAKE2b, retarget, checkpoints, UNIFIED digest) was found faithful, and no path in the plan broadcasts a fork transaction that is also valid on BTC. The problems are in what the engine trusts from the server, in the API shape the plan freezes, and in tests that did not prove what they claimed.
